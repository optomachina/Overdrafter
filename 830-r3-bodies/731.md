## Summary

OVD-748. The permit seam already aborts a signal at expiry and the session lease context carries a signal, but neither reached the provider adapters. A timed out or lease lost run kept driving the provider. This passes that signal into the adapters before session leases are turned on.

- `VendorQuoteAdapterInput.signal` is new and optional. `providerTaskPipeline` combines the seam signal and the lease signal and binds it with `withProviderAbortSignal`.
- The bind wraps `providerKillSwitchCheckpoint`, which every adapter already calls before navigation, upload, configure and save (Xometry, Fictiv, the portal kernel behind Quickparts and Geomiq, RMFG). Adapters stop at those safe points with no per adapter plumbing. `guardProviderQuote` keeps the abort check when it swaps in the guard.
- A new `ProviderAbortedError` is rethrown unchanged by adapters through `isDispatchDecisionError`, plus the three catch sites that only knew the kill switch (Fictiv modal dismissal, kernel retry loop, Xometry drawing fallback).
- Pipeline outcome is code `provider_aborted`. Disposition is `failed` before any provider mutation and `manual_follow_up` after one. It is never retried, never calls `onBlock`, and never turns the provider off for the day. An abort before launch leaves `adapterStarted` false.
- With no abort, the only change is an extra live signal on the input and checkpoint wrappers that pass straight through.

No SQL, migrations, lease RPC, auth or CI changes. In flight network calls are not cancelled, only the next safe point is. The Xometry route in `index.ts` that does not use the pipeline is not wired in this PR.

## Review round 1

Independent review requested changes. Both findings are fixed in 2651fab2, each with regression tests.

- **P1, abort during the launch guard.** `guardProviderQuote` checks the signal before the guard and again after it, before `onLaunch` and the adapter. Tests: pre-aborted signal, and an abort that lands during the guard. Neither fires `onLaunch` or the adapter.
- **P2, lease loss overriding manual follow up.** `leaseStop` no longer turns an aborted run into `failed / lease_lost`. When the adapter threw `ProviderAbortedError`, the outcome is classified by mutation phase, so an abort after a provider mutation stays `manual_follow_up / provider_aborted`, and one before any mutation is `failed` with no retry. Tests drive the real lease manager and memory store instead of the fake lease.
