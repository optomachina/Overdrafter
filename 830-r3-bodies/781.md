## Summary

This PR adds a **draft** schema for Jarvis channels: ten `public.jarvis_*` tables (including `jarvis_decisions` and `jarvis_control_commands`), RLS on every table, seven SELECT-only policies, explicit grants, and one read-only guard function (DM-8). It also adds a rollback, notes, a fixture against a disposable local Postgres, pending pgTAP, and an ephemeral-DB CI workflow. **Nothing is in `supabase/migrations/`, and nothing is applied to any Supabase project.**

## Problem

OVD-798 (ConversationService), OVD-804 (thread) and OVD-810 (run control) need a reviewed data model before any of them can land. The architect required it as a draft with RLS proof, applied only to a local fixture.

## Acceptance criteria addressed

- [x] All tables from the architect comment, with the specified keys and uniqueness: grants, channel settings, conversations (`user_id` UNIQUE), identities (`UNIQUE(channel, external_id_hash)`, HMAC hex only), link codes (≤10 min CHECK), messages, decisions (`best_guess NOT NULL`), control commands (`UNIQUE(graph_run_id, idempotency_key)`), inbound events (PK `(channel, idempotency_key)`), and outbound deliveries (`UNIQUE(message_id, channel)`).
- [x] RLS on every table, no anon grants, and authenticated can SELECT only its own rows. Grants and settings are readable only by an admin at AAL2. There is no client INSERT/UPDATE/DELETE: writes go through the service role only.
- [x] SECURITY DEFINER only where justified. The one guard function is justified in `ovd-797-notes.md`: it uses `search_path = ''` and fully qualified names, revokes from public/anon/service_role, grants EXECUTE to authenticated only, and checks `public.is_platform_admin()` + `public.current_user_has_aal2()`. It is not copied from `api_admin_set_provider_kill_switch`.
- [x] DM-1..DM-11 + DM-1R pass on a local disposable fixture (Proof below).
