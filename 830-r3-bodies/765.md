## Summary

**UI**
- `ProviderKillSwitchCard` and `SpendCapCard` go through a shared hook, `useAal2StepUp`.
- At AAL1, `MfaStepUpDialog` opens and the write is sent once, after verify.
- Cancel sends no RPC.
- With no enrolled factor, a `StepUpNoticeBanner` shows an "enroll MFA" message with a set-up button.

**CLI**
- `scripts/provider-kill.mjs` authenticates as service_role. The key comes from `SUPABASE_SERVICE_ROLE_KEY`, or from Secret Manager by name via `--secret-name` / `OVERDRAFTER_SERVICE_ROLE_SECRET_NAME` (fetched with `gcloud secrets versions access`). The key is redacted from all output.
- It calls new service_role-only kill RPCs. These write the same audit row with actor `cli:service_role`, plus the required `--operator` argument.
- The emergency brake never depends on MFA. Flipping stays an RPC call with no deploy.

**SQL**
- Draft only, in `docs/migration-drafts/ovd-771.sql` with a rollback.
- The audit `actor` column changes from uuid to text, and an `operator` column is added, with a check on the allowed shapes.
- The new service functions are SECURITY DEFINER with `search_path = ''`, revoked from public, anon and authenticated, and granted to service_role.

## Problem

OVD-767 makes the admin kill-switch and spend-cap writes require AAL2. Before that can ship, the UI needs a step-up, and the CLI brake must not depend on MFA.
