Fixes OVD-827: flaky `server/engineering/native-artifact-route.test.ts > ends the HTTP response on deadline even when the pool never resolves`. Under full-suite load it got `Connection: keep-alive` where it expected `close` (PR #783, CI run 38854275683).

## Root cause
This is a real production bug, not a test race. The route enforced its deadline only with a `setTimeout`. The inner private SQL and storage layers also check `performance.now()` against the same budget, and their deadline starts later than the route's. If a GC pause or CPU load stalls the event loop past the deadline, the inner layer sees the expired deadline first, aborts itself and resolves a 503 `transfer_unavailable` Response. That happens in microtasks, before the route's timer phase runs. The route's signal is still unaborted at that point, so it passes the inner 503 through with `writeHead(response.status, response.headers)`. That response has no `Connection: close`, so Node keeps the connection alive.

## Fix
- `native-artifact-route.ts` records `deadline = performance.now() + timeoutMs`. After the handler returns, it aborts if that deadline has passed. A response that finishes past the deadline now always goes through the `fail(503)` path, which sends `connection: close`. That's 4 added lines and no other behavior change.
- New deterministic regression test: the pool connect blocks the event loop for 50ms against a 20ms deadline. Without the fix it fails with exactly the CI error, `expected 'keep-alive' to be 'close'`. With the fix it passes.
- The original test is unchanged.
