## What changed
- `scripts/check-migration-immutability.mjs`: `supabase/migrations/` is append-only. A file passes only if it's newly added and its timestamp is after the newest base migration. Modified, deleted, renamed, copied and mode-only changes are violations. The checker runs in report mode (`--enforce` is off).
- **Scope cut (Blaine):** this PR covers migration immutability only. The design's prod-push scan (`supabase db push`, `--linked`, `--db-url`, `migration up`, `db reset --linked`, and the prod ref in runnable files) is **not** here and needs a follow-up issue. `docs/migration-immutability.md` says the same.
- The CI job runs the base copy of the checker, which closes the gap where the head-run node:test wrapper could be dropped from `test:portable-node` unreported.
- **Wiring (no workflow edit):** `scripts/check-migration-immutability.node-test.mjs` is added to `test:portable-node`, which CI already runs. It checks HEAD^1..HEAD in report mode, skips when HEAD^1 doesn't exist, and never fails on findings. There is also a new npm script, `migrations:immutability`, that compares against `origin/main`.
- **Review fixes (round 2):** the checker's "run only when invoked directly" guard now compares real paths. Before, a checker reached through a symlinked path (the macOS temp dir `/var/folders` is one) printed nothing and exited 0, which broke `test:portable-node` on every Mac and was a silent fail-open. The node-test wrapper also makes its temp dir under `realpath(tmpdir())`, so it works even when the base copy predates this fix. A force-push or restore timeline event with no usable `created_at` now makes the label override `unavailable` (fail closed). New tests cover a checker run through a symlinked directory and a symlinked file, importing it staying inert, and undated force-push/restore events.
- **Review fixes (round 3):** a `labeled` / `unlabeled` event for `migration-edit-approved` with a missing, null or unparseable `created_at` was ordered as time 0, so an undated unlabel left the waiver applied and an undated relabel by someone else was ignored. `evaluateOverride` now returns `unavailable` ("label event has no usable created_at") when any event for that label cannot be dated (fail closed); undated events for other labels change nothing. Tests cover an undated unlabel, an undated non-Blaine relabel, an undated first event, an unrelated undated label and the CLI end to end. `docs/migration-immutability.md` and the `evaluateOverride` doc comment say so. Draft job file only (not `.github/`): `${override[@]+"${override[@]}"}` so an empty array no longer fails under `set -u` on bash 3.2 (this fixes the 2 macOS-only vitest failures), and `test -s` on the JSON report after the node call. The docs now say workflow edits need Blaine's card before merge.
- **Review fixes (round 4):** the same fail-open came back a third time: `created_at` values that `Date.parse` accepts but GitHub never sends (`"1"`, `"2026"`, `"Oct 10"`, `0`, `[0]`, `2026-02-30T…`) were ordered as real dates, so an unlabel by Blaine or a relabel by someone else could still be hidden and the waiver applied. Instead of patching that case, `parseGitHubTimestamp` is now the only place the checker parses a date. It accepts only a string in GitHub's full ISO-8601 UTC form (`2026-10-10T09:00:00Z`, optionally `.123`) that round-trips through `Date`, so rolled-over dates (`2026-02-30`, `24:00:00`) and sub-millisecond fractions are rejected too. The push time (`--head-pushed-at`) and the `created_at` of every force-push, restore, labeled and unlabeled event the decision reads go through it. Any value it rejects makes the override `unavailable` (fail closed). Events for other labels and other event kinds are still not read. Tests are table-driven: GitHub's format with and without millis is accepted, and 39 malformed values are unusable (`"1"`, `"2026"`, `"Oct 10"`, `"2026-10-10 09:00:00"`, no `Z`, `+002026-…`, `2026-02-30T00:00:00Z`, numbers, `null`, objects, arrays and more). Each decision path (push time, force push, restore, labeled, relabel by someone else, unlabeled) fails closed on every one of them. A CLI test covers it end to end, and a source scan keeps `Date.parse` inside the helper. `docs/migration-immutability.md` has new "Timestamps" and "Fail closed" subsections. Migration filename timestamps are unchanged: they are 14-digit strings compared as text, never parsed as dates, and no approval depends on them.
- Tests: `scripts/check-migration-immutability.test.mjs` (vitest) plus fixtures. The lane-contract allowlist now includes the new portable suite.
- **Final round (orchestrator, 0d1069c9):** merged origin/main in (#821/#823/#827/#826/#816); `package.json` and `test-lane-contract.test.mjs` only conflicted because both sides appended a portable suite, and both are kept. Added the job to `ci.yml` with `persist-credentials: false`, every `${{ }}` through `env:`, and the checker exit captured instead of tripping GitHub's `bash -e`. The summary is always written, and a checker that crashes or exits without a report gets an ERROR line and turns the job red (still non-blocking). Tests now read the real `ci.yml` job (the draft fixture is deleted), run the step under `bash -e`, cover the crash and silent-exit cases, and allow 20s for the git-heavy groups.
