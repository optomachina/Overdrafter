## Summary

Adds journey tests that would have caught Jarvis shipping with no user-facing front door: a capability manifest of user-facing surfaces, a static reachability test over the real router/API, and a phone-viewport Playwright journey for the Jarvis front door marked expected-fail until OVD-805.

## Problem

Tests covered components (workers, CAD demo, flagged admin page) but nothing exercised a real user journey from a public entry point, so nothing failed when Jarvis had no front door.

## Acceptance criteria addressed

- [x] Reachability test driven by a capability manifest; a surface with no public, non-flagged, non-admin entry point fails CI (OVD-825 item 2). Known gaps are marked `knownMissing` and ratcheted: the test fails once they become reachable so the marker must be removed.
- [x] Front-door journey at 375px and 430px phone viewports, `test.fail()` until OVD-805 (OVD-825 item 1).
