## Summary

`evaluateProviderAdapterFailureContract` no longer treats page text as a purchasing action, and treats a visible quote-ready page ("Continue to Checkout") as terminal.

## Problem

In the T1 live run, a Xometry `saved_requirement_mismatch` error had no `payload.terminalState` and its `bodyExcerpt` contained "Continue to Checkout". The contract reported `finite_terminal_state_missing` and `purchasing_action_observed:bodyExcerpt.value` although nothing was clicked.

## Acceptance criteria addressed

- [x] `purchasing_action_observed` only from checkout/order terms under action-bearing keys (url/href, navigation, redirect, request, endpoint, route, click, action), never from `bodyExcerpt`/page text. Unsafe flags and checkout/order key names still caught.
- [x] Failure with no declared terminal state whose page shows "Continue to Checkout" classifies as `configuration_required` (quote ready, run stopped on settings). Declared-but-invalid states still report missing.
- [x] Tests: page text alone has no flags; simulated checkout click/navigation/request raises `purchasing_action_observed`; replayed T1 fixture passes.
