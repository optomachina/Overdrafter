Implements **OVD-829** (OVD-828 S1): one per-supplier settings framework for every supplier.

## Summary
- Migration **draft only**: `docs/migration-drafts/ovd-828-s1.sql` + `.rollback.sql`. Adds `daily_quote_cap` to `private.provider_kill_switches` (no default: null means unlimited, no backfill; when set must be > 0). Adds a durable `private.provider_daily_quote_usage` counter and a service_role-only `api_worker_reserve_provider_dispatch`, which checks the limit and increments the counter in one atomic step. The new admin RPC `api_admin_set_provider_settings` is SECURITY DEFINER with `search_path=''`, REVOKE/GRANT, auth check, `is_platform_admin()` and `current_user_has_aal2()`. Also adds the missing AAL2 check to `api_admin_set_provider_kill_switch`.
- pgTAP: `supabase/tests/pending/ovd829_provider_settings.sql.pending`.
- Worker: `providerKillSwitch.ts` becomes `providerSettings.ts`; the old path re-exports. One guard at the generic dispatch step. The kill switch beats the cap. If the on/off read fails, the supplier is treated as off. If the cap read fails (or the RPC is missing pre-migration), there is no cap. A cap applies only when an admin set a positive integer. Counting is durable in the DB.
- RMFG: removed `RMFG_DAILY_QUOTE_CAP`, the in-memory `quotesToday` counter and the daily-cap branch.
- OSHCut: #743 adds a separate per-process cap in `worker/src/providerDailyQuoteCap.ts`. Whichever of #743 / this PR lands second must replace that cap with this universal supplier settings gate (no parallel caps).
- Admin UI: each supplier row gets a cap input with an Unlimited option.
- Docs: `business-model.md` now says there is no quote cap by default; admins can set one per supplier (OVD-828). Decision: Blaine, Oct 16.

## Deploy notes
- Apply the migration **before** deploying the worker. Without the counting function, every live dispatch is refused.
- When the migration is promoted, `supabase/tests/ovd722_provider_kill_switch.sql` needs `aal2` claims, and `api_role_privilege_inventory.sql` needs a row for the new RPC.

## Deploy gate (added after Opus review)
- New worker flag `WORKER_PROVIDER_DURABLE_DISPATCH_CAP` (default `off`). Off: kill switch still fails closed; cap read failure = no cap; per-process counting only for suppliers with an admin-set cap. Turn `on` only after `docs/migration-drafts/ovd-828-s1.sql` is applied in a Blaine-approved window; rollback = flag off first.
- Operator CLI tools (vendorWorkflowSmoke, xometryQuantitySweep) now go through the same dispatch gate, so any admin-set cap (e.g. RMFG) applies on every path.

## Scope change (Oct 16)
Blaine decided there is **no default daily quote cap**. `DEFAULT_PROVIDER_DAILY_QUOTE_CAP=20` and all hard-coded 20/day caps were removed; `daily_quote_cap` defaults NULL (unlimited). With `WORKER_PROVIDER_DURABLE_DISPATCH_CAP=on`, an unavailable counter refuses only suppliers with a readable admin-set cap. A corrupt stored cap (<= 0) is treated as no cap. The PR template / `validate-pr-body.mjs` / go-live checklist item "about 20 quotes per provider per day" is intentionally left unchanged here: editing the PR-body gate needs a separate human `Gate change review`, so it is a follow-up.
