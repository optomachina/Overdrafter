## Summary

Operator CLI tools that reach live providers now read the OVD-722 kill switch before any provider call and refuse when it is engaged or unreadable.

- New `worker/src/tools/operatorKillSwitchGate.ts` wraps the existing `assertProviderKillSwitchDisengaged` and `supabaseProviderKillSwitchReader`. It uses the existing read RPC only. No SQL, migration, schema or write path changed.
- `runEvaluationBatch` in `vendorWorkflowSmoke.ts` checks every requested vendor before file staging, config or registry work, then again before each quote. This covers `smoke:vendor-workflow`, `eval:live-provider` and `sweep:fictiv-quantity`, which runs through the same batch.
- `xometryQuantitySweep.ts` checks Xometry first in `main`, before staging or adapter construction.
- A refusal is a `ProviderKillSwitchError`, so the tool prints its message and exits 1. The global switch is honored because the RPC state folds it in.
- Fail closed: missing `SUPABASE_URL` or `SUPABASE_SERVICE_ROLE_KEY`, an RPC error, a timeout or a malformed response all refuse.

Not covered, on purpose: `probeProviderSession` and `probeXometryProfileAuth` are designed to run with no database credential (Cloud Run job isolation), so adding a read would change that boundary. Worth a follow up decision.

Note for operators: these tools now need the service role env vars to run, since they must read the switch.
