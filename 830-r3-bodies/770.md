## Summary

Xometry offer parsing accepts a bare `$` amount only when the provider's registry currency is USD; otherwise it fails closed with `price_currency_unverified`.

## Problem

The saved T1 Xometry quote page shows bare amounts (`$41.41 ea.`, `$414.15`), but the parser required an explicit USD marker, so live price capture would fail closed on real pages. There was no registry currency field to decide this from.

## Acceptance criteria addressed

- [x] Bare `$` parses only when registry currency is USD; non-USD or missing registry currency fails closed with `price_currency_unverified`.
- [x] Explicit `USD` / `US$` forms still parse.
- [x] `C$`, `A$`, `€`, `£` rejected even with a USD registry.
- [x] Thousands separators handled (`$1,234.56`).
- [x] Tests on scrubbed T1 text.
