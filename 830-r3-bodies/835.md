## Summary

Adds a weekly evals report built only from signals we already have. There are no LLM calls and no paid eval service. `scripts/evals-weekly-report.mjs` reads merged PRs and their linked Linear issues through `gh`, with cached reads. It computes first-pass CI/QA pass rate and cost per accepted PR as defined in [`docs/agent-graph-metrics.md`](https://github.com/optomachina/Overdrafter/blob/main/docs/agent-graph-metrics.md#cost-per-accepted-pr). It writes a markdown report comparing a 14-day baseline with the current week, plus a before/after (and A/B) section for each registered experiment. Any experiment that breaks its stop rule is flagged: cost per accepted PR up more than 25% with no pass-rate gain.

## Problem

When we change a process, prompt, routing rule or agent, we have had no cheap way to tell whether it was an improvement and whether it was worth the cost.

## Scope

**How the metrics are computed:**
- **Accepted:** merged with a green head rollup. The `Vercel` and `CodeRabbit` checks are ignored by default (`--ignore-checks`), since they are infra or advisory: the Vercel failures are "Resource is limited".
- **First-pass CI:** the first commit with check runs is all green. Up to 3 later commits are probed when the first commit has no check runs.
- **QA:** taken from `QA: PASS|FAIL` comments.
- **Repair rounds:** taken from the repair-budget and round comments; a QA FAIL or an Opus CHANGES REQUIRED counts as at least 1.

**Cost:** cost comes only from a spend ledger (`--spend-ledger`, JSONL with `ts` and `usd`, plus optional `pr`, `issue`, `agent`, `source`). The repo has no ledger today, so every cost field prints "not available (no spend ledger)". Nothing is estimated.

**Cache:** merged-PR details and first-commit check runs are cached forever by SHA. The PR list uses a 1-hour TTL. With a warm cache, a rerun took 91 `gh` calls with 477 cache hits; a cold run took about 4 minutes.

**Not included:** no workflow or scheduler, no package or lockfile changes, no new dependencies, and no spend-ledger collector. The collector is the follow-up needed before cost per PR has numbers. There are no active experiments yet.
