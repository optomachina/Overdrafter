The Xometry upload checkpoint used to deny every staged STEP/STP selection whenever the live accept list was broader than admission (`format_added`). This PR implements Option 1 from the OVD-863 design:
- Selection is allowed when every staged extension (case-insensitive, leading dot stripped) is in `allowedExtensions`, which is admission ∩ live accept.
- `format_added` only logs drift.
- `format_removed` denies only when a staged extension was removed from the live list.
- These still fail closed: a missing, empty or unparseable accept list (the reviewed Xometry missing-accept identity is unchanged), and any staged extension outside admission.
- No migration. Admission stays step/stp.

The regression test (accept `.step,.stp,.sldprt` + staged `.step` must select) was written first and failed on main. The other six design cases are covered too.
