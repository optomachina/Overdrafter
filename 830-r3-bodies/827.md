1. **Fail closed on unknown categories.** `validateFindings` rejects any finding whose category is a string outside `CATEGORIES`, so the CLI exits 2. `other` is still valid, and `Test Gap` / `test_gap` still normalize to `test-gap`.

Now `validateFindings` and `validateLedger` share one `categoryProblem()` check that tests `typeof === "string"` before normalizing and reports `category must be a string` (exit 2). `normalizeCategory` itself returns `""` for any non-string, so it cannot throw on any JSON value. A missing or null category still reports `category is required`.
3. **Two siblings of the same defect, fixed the same way** (not named in the review): a ledger `task` that is not a string (`String(entry.task)` threw) and a finding `title` that is not a string (interpolating it into the text report threw). Both crashed with exit 1 on `{"toString":null}`. `task` must now be a string matching `OVD-<number>`, and only string titles are reported.
4. **Default ledger from the repo root.** `resolveDefaultLedgerPath()` derives the root from the script's own location (`path.resolve(path.dirname(fileURLToPath(import.meta.url)), "..")`), not from `git`. There is no subprocess in the script. Why: an earlier commit of this PR resolved the root with `git rev-parse --show-toplevel` through `node:child_process`; SonarCloud `javascript:S4036` (code-scanning alert #261) flagged that PATH-resolved call. `main` never had a subprocess. Passing `--ledger` explicitly works as before.

   OVD-881 criterion 2 names `git rev-parse --show-toplevel` as the method. This meets the criterion's intent: the ledger is found at the repo root, not the current working directory, and is tested from a subdirectory and from an unrelated cwd.
5. **Trailing `--ledger` with no value exits 2** (`cannot read input`), the same as `origin/main`, instead of falling back to the default ledger.
6. **Docs.** `docs/review-findings-to-rules.md` now documents the exit codes (0, 1 only with `--fail-on-needs-task`, 2), every exit-2 case including off-taxonomy and non-string categories, and that the default ledger is found from the script's own repo root.
