## Summary

The OpenAI drawing-extraction request now uses a strict zod schema with no `default` keywords. Before this change, every OpenAI model fallback failed with `400 Invalid schema ... $ref cannot have keywords {'default'}`.

## Problem

`worker/src/extraction/schema.ts` uses `.default()` on `reasons` and `titleBlockSufficient`. `zodTextFormat` emits those defaults on a `$ref`'d sub-schema, and OpenAI strict structured outputs reject that. I found this during the T1 overnight live end-to-end run, on the in-repo sample drawing `test-fixtures/quoted-sample/1093-05589-02.pdf`.

## Acceptance criteria addressed

- [x] The OpenAI request format has no `default` keywords and requires every property (unit test).
- [x] Anthropic and OpenRouter parsing keep the tolerant defaults (unit test: a response missing `reasons`/`titleBlockSufficient` parses with `[]`/`true` under `modelResponseSchema` and is rejected by the strict schema).
- [x] The prompt version hash is unchanged: a unit test pins `MODEL_FALLBACK_PROMPT_VERSION` to `sha256:24595ac5e265`, the value computed on main before this change.
