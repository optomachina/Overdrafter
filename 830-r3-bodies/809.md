## Summary
Adds eval rubrics for the repo's agent skills, plus offline tooling that scores them with a judge from a different model.
- `evals/skills/<skill>/spec.json` covers 15 skills: the 8 in `.agents/skills` (including verify-overdrafter, merged in #801 as d934d4ee) and the 7 in `.codex/skills`. Each skill has 2 cases with a task, expected behaviors, and a rubric whose points sum to 10.
- `docs/skill-evals.md` describes the loop. Model A runs the skill and a different model B judges it. The loop repeats until every case is 10/10, or stops after a bounded number of rounds and reports the gaps. A skill's evals should be re-run on any change under its skill dir or its spec. `changed` lists those skills, but it only compares commits, so the docs say to commit before trusting the list, empty or not. `skillHash` makes older scores `stale`. No CI workflow runs the evals or the CLI. But CI does enforce the spec rules: see "CI impact" below.
- `scripts/skill-evals.mjs` has five commands. It makes no model API calls.
  - `validate`: specs are well formed, each tracked skill has exactly one root and a spec, and each spec has its skill directory. A tracked skill whose files are deleted from the working tree no longer counts as present. Otherwise it exits 1.
  - `changed --base --head`: lists the skills whose dir or spec changed between two refs, including deleted and renamed skills. Loose files directly under a skill root (such as a README) are not listed. It reads NUL-separated git output, so a change to a file with an accented, tab, newline or quote name still lists its skill.
  - `check-judge --runner --judge`: exits 2 unless both are non-empty and are different base models. Aliases, provider prefixes and dated snapshots of one model count as the same model.
  - `hash <skill>...`: prints the `skillHash` a judge result must carry. It exits 2 for an absent skill or a name found in two roots.
  - `report [--json] [--skill <name>]... <scores.json>...`: aggregates judge results.
    - It exits 0 only when `validate` passes, at least one skill is in scope, and every in-scope case is 10/10. The one exception is `--skill ""` (nothing changed), described below. Otherwise it exits 1.
    - The `validate` check applies to scoped runs too. A skill with no spec, a spec with no skill, or a name in two roots fails every report.
    - `--skill` scopes a run; it is repeatable or takes a comma list.
    - `--skill ""` is the documented pipeline's "no skills changed" case and the one report that passes with nothing scored. It prints "no skills changed" with `Overall: nothing to re-score` (never `PASS`; `--json` carries `nothingToRescore`, which the docs describe), exits 0 and reads no scores file, but still runs the `validate` checks (a broken repo exits 1).
    - `changed` only compares commits, so in a git checkout `--skill ""` exits 1 with "uncommitted skill changes; commit first" (and lists the paths) when it finds any of these under a skill root or `evals/skills`:
      - anything `git status` reports there: a staged, unstaged, deleted or renamed change, or an untracked file that is not gitignored;
      - an untracked file other than `.DS_Store` under `evals/skills`, gitignored or not;
      - an untracked file other than `.DS_Store`, or a wholly untracked directory holding one, under a skill root that holds a tracked file, gitignored or not (here `.agents/skills` and `.codex/skills`).
    - Plain `git status` never lists an untracked file that git ignores. This repo gitignores `.agents/`, `.codex/` and `skills/`, so it misses a new file in `.agents/skills` or `.codex/skills`. `evals/skills` is not ignored here (`!evals/skills/`), but it is listed directly all the same, so a later ignore rule covering `evals/` would not hide a new spec. The guard lists these files directly with `git ls-files --others` (ignored or not). A wholly untracked directory is listed once as `dir/`; if its files are not gitignored (as under `evals/skills` here), `git status` reports them too and they are listed as well.
    - Left alone: gitignored files in a skill root with no tracked file (`.claude/skills`, `.cursor/skills`, where third-party skills are installed locally), anything outside the skill roots and `evals/skills` (such as `.codex/config.toml`), and `.DS_Store` files and empty directories. The untracked listing skips `.DS_Store` and empty directories, `git status` never lists an empty directory, and this repo gitignores `.DS_Store`. A third-party skill installed under `.agents/skills` or `.codex/skills` does trip the guard, because it looks the same as a new skill; the docs say to run the check from a clean checkout or worktree.
    - Only the exact empty string `""` means "none changed". A blank value (only spaces, a tab or a newline), a bare `--skill` or an entry like `a,,b` exits 2.
    - A case with no result is `unscored`, and a case with only older-`skillHash` results is `stale`. Both fail.
    - It exits 2 for no scores file, a malformed score file, or `--skill` with an unknown name, no value or a blank value.
- `.gitignore` gets `!evals/skills/`, because the existing `skills/` rule would otherwise ignore the specs.

The branch merges `origin/main` (no rebase), so it includes #801.
