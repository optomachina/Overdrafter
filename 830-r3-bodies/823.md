**Scope: the adapter import lint only, as Blaine asked.** The `CertifiedProviderId` branded type, `certify()` and the dispatch signature changes from the design are **not** in this PR.

**This is a report-mode baseline, not yet the boundary the issue describes.** The issue says only the dispatcher and adapter tests may import adapters. The allowlist below is wider than that: it exempts 14 non-dispatch production files, all worker tests and `worker/test-support/**`. Each exempt file can import any adapter silently in report mode. That is a deliberate first step (warn, with every existing importer listed), but it is the main thing to sign off on.

## What changed
- `eslint.config.js` adds two import rules at **warn** (report mode): `@typescript-eslint/no-restricted-imports` for ts/tsx files (type-only imports allowed) and the base `no-restricted-imports` for js/mjs/cjs files. Both use the pattern `(^|/)adapters(/|$)`, which matches any import path containing an `adapters` segment. It is not anchored to `worker/src/adapters`.
- An allowlist block (`eslint.config.js:18-48`, applied at `:101-106`) turns the TypeScript import rule **off** for the files listed in the next section. The block does not touch the js/mjs/cjs rule, but every allowlist entry is a TypeScript file.
- It also adds `no-restricted-syntax` at warn, banning `as CertifiedProviderId` and `<CertifiedProviderId>` casts. The selector matches the unqualified type name only, so `as P.CertifiedProviderId` and a cast through a type alias are not flagged. The type doesn't exist yet, so the rule is harmless for now.
- `scripts/eslint-adapter-import-boundary.test.mjs` has 6 vitest tests that run ESLint's Node API with the repo config. They check that an adapter import is flagged (severity 1) from a route file, from a non-allowlisted worker module and from a plain `.mjs` file, that `worker/src/index.ts` and a type-only import are not flagged, and that a `CertifiedProviderId` cast is flagged. No test covers an adapter test file importing an adapter (it lints clean today; see the pre-flip list).
- There is no behavior change, and `eslint .` is clean today. With the allowlist block removed, the rule flags 34 files and 61 messages. 19 of the files are tests or test-support. The other 15 are production: `worker/src/index.ts` plus the 14 non-dispatch files below. I reproduced the 34 and 61 figures at `d3f726a5`, and QA and Codex got the same numbers.
- No `.github/` changes, no deps, no migrations. This touches a sensitive path (provider dispatch), so merging needs Blaine's OK.
