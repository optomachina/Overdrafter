## Summary
Weekly upkeep for the verify-overdrafter feature map. Each run opens at most one PR.
- **`scripts/verify-skill-drift.mjs`** is a read-only, deterministic drift detector.
  - It compares the feature map against the routes in `src/App.tsx`, the specs under `e2e/`, and the paths the map refers to in inline code. Fenced code blocks are skipped at any indent, including inside list items.
  - It writes a JSON report and a markdown report. Exit codes: 0 means no drift, or no skill at the default path. 1 means drift. 2 means a usage or config error. An explicit `--root` or `--skill-dir` that does not exist exits 2 and is never reported as "absent". A flag whose value is missing or is another flag (`--root --json`) also exits 2.
  - An optional `drift-ignore.json` lists exclusions, and each entry needs a reason.
  - It has a `select-pr` mode, backed by a pure function. Only an open same-repo PR whose head is the fixed branch `chore/verify-skill-maintenance` is the maintenance PR (`update`). The label `verify-skill-maintenance` is optional. A PR with the label or branch name on another branch or a fork goes in `foreign`, and the runbook never touches it. If there is no maintenance PR, the mode returns `create` on the fixed branch, so there is never more than one. Rows that aren't `gh pr list` objects exit 2.
- **`docs/runbooks/verify-skill-maintenance.md`** is the weekly runbook. The agent runs pstack `maintain-verification-skill` against the report, then opens a PR or updates the existing one. The PR lookup runs each `gh` query on its own and checks each exit status explicitly; it does not rely on `set -e`. A failed query, or one that prints `null`, nothing or anything but one JSON array, stops the block. It is never read as "no PR".
- **`.github/workflows/verify-skill-drift.yml`** runs on a weekly cron and on `workflow_dispatch`. It only runs the detector and uploads the report. It has `contents: read`, no secrets, and no `pull_request_target`, and it checks out without saved credentials. When it finds drift, the run fails so the drift is visible. The workflow never opens a PR itself; the agent does that, following the runbook. This round did not change the workflow.

## Repair round 4 (Codex review @ 18c2aaef: `verify-skill-maintenance.md:48-57`)
**The runbook PR lookup no longer depends on `set -e`.** bash turns errexit off for a command on the left of `||` or `&&`, in an `if` condition and under `!`. So the round 3 block (`( set -euo pipefail ... )`) still reached `select-pr` and printed `"action": "create"` with exit 0 when a failing `--head` query was followed by `[]` from `--label`, if it ran as `block || ...` or inside `if`. I reproduced that with a fake `gh` first.
- The block now runs each `gh` query on its own and checks each exit status (`gh ... > file || { echo "...failed" >&2; exit 1; }`). `mktemp` is checked the same way.
- Each query must print exactly one JSON array. `null`, nothing, an object, a string, or two arrays stop the block. Only then are the two lists combined, and a failed combine stops the block too.
- The `( ... )` subshell is kept so `exit 1` cannot close the operator's shell. An EXIT trap removes the temp dir and keeps the exit status. The block ends with `select-pr`, so its status (`2` on bad rows) is the block's.
- The fixed-branch-only selection from round 3 is unchanged.
- Other runbook blocks: the only other command block is the single `node scripts/verify-skill-drift.mjs ...` call, which has nothing to chain. The workflow's one `run:` step is also a single command. No other block uses `set -e`.
- Tests: the runbook block is extracted verbatim and run in four contexts (plain, `{ block; } || echo FAILED`, `{ block; } && echo PASSED`, `if block; then ... else FAILED`) in every distinct bash on the machine. Cases: head query fails with `[]` from label; label query fails with `[]` from head; a failing `gh` that still printed `[]`; `null`, empty, `{}`, a string and two arrays on either query; a failing `jq -s add`; a `select-pr` error; and the success paths (`update` plus a foreign PR, and `create`). A regression guard fails if any runbook command block uses `set -e`, `errexit` or `pipefail`, and a cleanup test checks the temp dir is removed on success and on failure.
