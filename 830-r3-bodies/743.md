## Problem

The v1 locator table did not match the live DOM. There is no `select[name=material]` and no `data-oshcut-quote-option-*`; sign-in is a modal; routes are `/cart/O-<uuid>`. As a result, every live attempt would have ended in `selector_drift`. Test parts uploaded by captures also stayed in the cart.

In QA, the off-host fixture test was flaky and new-code duplication was 3.7%, above the 3% limit.

### Flake root cause

The test page runs `location.assign("https://login.example-sso.com/…")` from the upload `change` handler. Under load, that navigation lands while the kernel is in the quantity `fill`. Three things then happen:

1. The route guard records `unexpected_navigation:login.example-sso.com` and aborts the request.
2. Chromium commits its error page, and `framenavigated` overwrote the violation with `unexpected_navigation:chromewebdata`.
3. The `fill` waited on that navigation and timed out with a plain Playwright `TimeoutError`. `translatePortalKernelError` ignored the recorded violation and returned `selector_drift / ambiguous_provider_mutation`.

The race is in kernel code that is also on main; this branch did not change it. The fix is in production code only: the first violation is kept, and a recorded violation wins over any later error. Kill-switch and dispatch-decision errors keep their existing precedence. The test was not changed.
