Fixes OVD-867. This is a separate PR stacked on #813 (base `bwilson/ovd-844-sensitive-class-detector`), so #813 isn't touched.

Build model: **sonnet** (source: Grok Bot's handoff; OVD-867 has no model label).

## What
- New exported constant `MAX_SQL_WORDS = 100_000`. `detect()` counts the whitespace-separated words in each head `.sql` body before scanning it.
- A body over the limit fails closed. It's skipped by the scanner and assigned every class the SQL content rules can produce, so it counts as sensitive. Its reason is `sql:oversized:<count>><limit>`. The status stays `ok`, so the result no longer reads as a generic detector error.
- **New `manual_review` field** in the result JSON, present only when a body was rejected. It holds: `SQL body <path> rejected for size: <N> words exceeds the limit of 100000; manual review is required`. `formatSummary` prints it as a `- manual review:` line. Any consumer that reads the JSON strictly should know about this field.
- Tests: a body exactly at the limit is scanned normally, one word over fails closed with that exact message, and two runs give identical results.

## Scope
Only `scripts/sensitive-class-detect.mjs` and its test file change. The workflow file is untouched.
