## Summary

This PR adds a `## Proof` section to the PR template. It also adds a pure parser, `scripts/proof-check.mjs`, and a read-only `proof-check` workflow that starts in `PROOF_CHECK_MODE=report`. The parser has a separate `journey-test` rule, added for OVD-825: a user-facing change (`src/**/*.tsx` or `src/**/*.css`) must reference an `e2e/journeys/*.spec.ts` file or that journey test's Actions run.

## Problem

Nothing currently makes a PR show how it was verified. This PR makes the body carry concrete proof: a test, a command with its output, a live link or a screenshot. UI changes must also include a screenshot and a journey test.

## Acceptance criteria addressed

- [x] The template has a Proof section with Test, Command (plus a fenced output block), Live and Screenshot items, and the `<!-- proof: replace me -->` placeholder.
- [x] `checkProof(prBody, changedFiles)` returns `{status: pass|fail|exempt, reasons[]}`. Docs-only PRs are exempt. The check fails when the section is missing, is empty, is only the placeholder, or has no recognised item, and when a UI change has no Screenshot.
- [x] The workflow is read-only (`contents: read`, `pull-requests: read`) and runs the base branch's copy of the script. It writes a job summary and starts in report mode. It is not a required check.
- [x] Separate `journey-test` rule (`checkJourneyTest`), also in report mode, with its own tests.
- [x] Parser unit tests and a test that runs a fixture event payload through the workflow.
