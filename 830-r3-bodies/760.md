## What

OVD-381 acceptance criterion 4 (provider sessions isolated): the OVD-462 session lease is now wired into the OVD-464 generic provider route. Before this change, `index.ts` passed no lease port, so `WORKER_PROVIDER_SESSION_LEASE=on` always stopped with `session_lease_unavailable`.

- `worker/src/providerTaskLeasePort.ts` (new) adapts `createProviderSessionLeaseManager` and the RPC store to `ProviderTaskLeasePort`.
  - Identities are HMACs under a new secret, `WORKER_PROVIDER_SESSION_NAMESPACE_KEY`, over provider, environment and slot (`default`). That is one storage-state slot per provider per deployment, which is what exists today.
  - Terminal adapter outcomes map to blocking lease outcomes (`blocked`→`provider_blocked`, `banned`→`account_banned`), so a blocked binding stays blocked across tasks.
- `config.ts`: with the lease on, the worker refuses to start unless the namespace key is valid (hex or base64, at least 32 bytes). The error message never echoes the key.
- `index.ts` builds the port only when the lease is on and a key is present. Otherwise the existing fail-closed `session_lease_unavailable` happens before the preflight, as before.
- Stale comments fixed: lease "not on main", and "no generic envelope reviewed in code" in `providerDispatchPreflight.ts` (Fictiv, Quickparts and Weerg are reviewed). Docs updated: `docs/provider-session-lease.md` gets a "Worker wiring" section, plus `ARCHITECTURE.md`.

## Behavior and rollout

- Default stays `WORKER_PROVIDER_SESSION_LEASE=off`, so production behavior is unchanged until an operator turns it on.
- Xometry stays on its specialized path and is not leased.
- Deploy wiring for the new secret is left to the deploy track.
- The lease RPCs and table are already applied in production (window 1, `20261012212325`).
- Rollback: set the lease setting off, or revert this commit.
