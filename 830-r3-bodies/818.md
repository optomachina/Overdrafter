## OVD-873: one sensitive-path list (JSON) + shared matcher (report mode)

Parent: OVD-870.

### What changed
- **`docs/sensitive-paths.json`** is the single source of truth: `{version: 1, classes: {schema, migrations, auth, payments, provider_dispatch, secrets, infra_ci, deps}, globs: [{glob, class}]}`. It has 53 globs:
  - 38 translated from the old AGENTS.md table;
  - 3 new schema globs (see below);
  - `**/*providerAdmission*`, `**/*providerUpload*`, `**/*provider_admission*` and `**/*provider_upload*` (each `{,/**}`);
  - 8 `infra_ci` globs for the files that define and apply the list (repair item 4 above).

  The provider globs were added for this reason: the table's hyphenated provider globs missed camelCase files such as `worker/src/providerUploadCapability*.ts`. Two changes from the table: `rls` now matches only at the start of a name or after `-` or `_` (`rls*`, `*-rls*`, `*_rls*`), so `urls.ts` no longer matches. That is not a general word boundary: camelCase and dotted forms such as `applyRlsPolicy.ts` and `foo.rls.ts` do not match this glob. The other change: the "schema" class gains `**/*.sql`, `supabase/config.toml` and `docs/migration-drafts/**`.
- **`scripts/lib/sensitive-paths.mjs`** is the one matcher, with no dependencies. Globs follow picomatch semantics with `{dot: true, nocase: true}`. Supported syntax is `*`, `**`, `?` and `{a,b}`; anything else is rejected. One deliberate difference from picomatch: `**` also crosses a name containing a newline (picomatch's does not), so such a name cannot slip past. A backslash is a file-name character. A path also matches through any other reading of it (`pathCandidates`), so the result is a superset of picomatch on the raw name. It exports `createMatcher`, `classifyPaths`, `pathCandidates`, `triageRoute`, `checkAgentsParity`, `findGateLoosening`, `readSensitivePathsText`/`loadSensitivePaths` (which throw `BaseRefError` for an unreadable ref) and `GATE_CODE_FILES`, plus a CLI:
  - `classify [--base-ref <ref>] [--json] <paths>` is what triage and shell gates call. It exits 2 if `--base-ref` is given and does not resolve.
  - `report --changed-files-from … --base-ref HEAD^1 [--json-out]` is the CI report. The changed-files input is `git diff --name-status -z --no-renames` output, which is NUL-separated and leaves names unquoted. Newline output with git's quoted names is unquoted as well.
- **AGENTS.md**: the table is replaced by a human-readable list between `<!-- sensitive-paths:begin/end -->` markers, and the text now names the JSON as the source of truth.
- **`scripts/validate-agent-contract.mjs`** checks parity in both directions. A glob or class that is in the JSON but not in AGENTS.md fails, and so does the reverse. A missing JSON file or missing markers also fail.
- **Consumers.** None of them copies any globs.
  - `scripts/jev-pr-screen.mjs` raises the declared deterministic tier to `risky` when any file matches the list. It never lowers a tier, and it logs `sensitiveClasses`. No list value turns the check off: anything other than a valid list screens `risky`, and only `{ skipSensitivePaths: true }` on `deterministicTier`/`decisionRecord` skips it (tests only). With `--base-ref <ref>` (CLI) or `baseRef` (`screen()`), it reads the list from the PR's base, so a PR that narrows the list cannot lower its own tier. Without it, the working tree's copy is used and the CLI prints a warning. If the list cannot be loaded (a bad or empty ref, or missing or invalid JSON), every PR screens `risky` and the record has `sensitivePathsUnavailable: true`. `files` takes strings or `{path}` objects. A missing, empty or malformed list screens `risky`, with `filesProblem` set.
  - The triage skill (`linear-triage-router`) calls the CLI.
  - `docs/agent-log/README.md` is updated to match.
- **Gate loosening.** The report reads the JSON from the **base** checkout. The following are classified `gate_loosening`:
  - removing, narrowing or reclassifying a glob
  - deleting or breaking the JSON
  - editing the matcher, its report runner, the Jev screen, the parity check, the shared fixture or the planned workflow

  Adding a glob is free.
