## Summary

The portal kernel no longer fails a run because the provider's own page loads third-party telemetry. Off-host subresources and beacons are still aborted, so nothing leaves the browser. They are logged as `boundary.blocked_offhost` (host and resource type only) and counted in the run evidence. Off-host top-level navigation, and any off-host request that carries a credential header or a non-report body, is still a hard `boundary.violation`.

## Problem

`installPortalBoundaryGuards` set `boundary.violation` for every off-host request. OSH Cut's page posts a Datadog CSP report (`csp-report.browser-intake-datadoghq.com`), so the T1 live run stopped right after login with `unexpected_request`. Every real provider page loads analytics, so as written no portal-kernel provider could finish a live quote.

## Acceptance criteria addressed

- [x] Off-host navigation in the main frame is still a violation that aborts the run.
- [x] An off-host request carrying our payload (upload or any non-report POST body, or an Authorization/Proxy-Authorization/Cookie header) is still a violation.
- [x] Other off-host subresources and beacons get `route.abort("blockedbyclient")`, are logged as `boundary.blocked_offhost`, are counted in evidence (`portalBoundary.blockedOffhostCount` / `blockedOffhostByHost`), and the run continues.
- [x] Optional per-provider `offHostAllowlist` in the provider registry. It takes exact hostnames only and is empty for every provider. Payload and navigation rules still apply to allowlisted hosts.
- [ ] One live OSH Cut run: **deferred to an approved operator.** This work makes no live vendor calls, and OSH Cut is parked to 1.1.

## Scope

Included: the kernel request classification, telemetry and evidence count, the registry allowlist field (empty), tests and docs.
Not included: a live OSH Cut run, deferred to an approved operator. No provider's `liveAdapter` or egress changes, no allowlist entries, nothing in `supabase/migrations`.

Known limitation: an off-host beacon whose body is not a CSP or Reporting API report (for example a Datadog RUM `text/plain` batch) is treated as possibly ours and is still a violation. This is deliberately conservative. Loosening it would be a reviewed follow-up if the operator's live run hits it.
