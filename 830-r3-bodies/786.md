Fixes OVD-826: the flaky off-host browser test `providerPortalKernel.offhost.browser.test.ts > still stops when the page navigates the main frame off the provider host`.

## Root cause
Under load, the fixture's `location.assign` to an off-host URL races the quantity fill. The blocked navigation then commits Chromium's error page (`chrome-error://chromewebdata`), and its `framenavigated` event **overwrote** the recorded violation. Then the fill times out with a plain Playwright error. `translatePortalKernelError` mapped that error to `selector_drift`/`ambiguous_provider_mutation` without checking the recorded boundary violation, so the outcome depended on which event happened first.

## Fix (Release design)
- `recordBoundaryViolation` keeps the **first** violation (`??=`) at every violation site: route, websocket, popup/page, and main-frame `framenavigated`. The origin check still runs synchronously when each main-frame navigation commits.
- New pure `classifyPortalBoundaryOutcome` is the single precedence rule: `unexpected_origin` > `ambiguous_provider_mutation` > `selector_drift`. A recorded violation or an off-host current URL is terminal and replaces any in-flight step classification.
- `translatePortalKernelError` goes through the classifier.
- No sleeps, retries or timeout widening. The existing browser test is unchanged.

## Tests
- Classifier: simultaneous off-host, mutation and drift signals give `unexpected_origin`.
- Classifier: an off-host signal that arrives after a pending drift still gives `unexpected_origin`.
- Classifier: same-origin drift stays `selector_drift`.
- Kernel repro (fake browser): the fill navigates off-host, then to `chrome-error://chromewebdata`, then times out. Expected result: `unexpected_origin` with reason `unexpected_navigation:login.example-sso.com`.
