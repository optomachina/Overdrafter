## Summary

This PR adds the window 2 run sheet (`docs/release/window-2/README.md`), its pins (`manifest.json`) and a full rehearsal of the Jarvis chain. The rehearsal runs inside the existing `Disposable staged SQL proof` job, so hosted CI repeats it on every head. It also fixes the review findings from #702, #619 and #620.

**OVD-558 now runs as `postgres` (option A, decided by the lead).** Hosted Supabase connects as `postgres`, which is not a superuser and cannot act as `supabase_storage_admin`. The OVD-558 forward and reverse, like every other step, now run as `postgres`:
- The statements that acted as `supabase_storage_admin` are removed. Storage functions keep the access rights Supabase ships.
- The postflight proves, on the live catalog:
  - outside `storage`, the verifier can call exactly the 7 application functions;
  - inside `storage`, it can call exactly the functions `anon` can call;
  - that `storage` set equals the 20 names pinned in the manifest, so a Storage upgrade fails closed;
  - it holds no privilege on any `storage` table that `anon` lacks.
- **Accepted gap:** `storage.delete_leaf_prefixes` and the other Storage definer functions stay callable by the verifier exactly as by anon, and by nothing more. Option C (the verifier gets no `storage` USAGE; signed URLs, or a `service_role` fetch after a definer check) is a 1.1 follow up the lead is filing.
- The catalog digest is taken with `search_path = pg_catalog`, so every role prints the same value. The pins are regenerated: prechange `e1947671…`, post change `be97ed54…`. The production go or no go digest runs as `postgres`.
