## Summary

Adds `src/features/jarvis/`, which holds the `ChannelAdapter` interface, the shared `ConversationService` pipeline, an in-memory `JarvisRepo`, capability-based rendering, outbound delivery with retry and backoff, a `TestAdapter`, and the channel registry. The `DesignGraph` interface is the only exit to work. All of it sits behind the server-side flag `JARVIS_UI_ENABLED`, which defaults off, and nothing in the app imports it yet.

## Problem

Every Jarvis channel (web, Slack, Telegram, iMessage) needs one shared, tested front door. It has to enforce flag, channel, signature, idempotency, identity, tier and rate-limit gates in a fixed order, and it must not be able to reach workers except through the design graph. Without it, each channel would re-implement those checks.

### Repair round 2 @ dd519c4b (fixes Opus re-review N1 + minors 1, 2, 5)
- **N1:** `routeSubmit` now registers the run as "linking in progress" before calling `graph.submit`. When `handleGraphEvent` gets an event for a run it can't find yet, it waits for in-flight submits to finish and looks again, then processes that run's events in order. So events pushed synchronously during submit, including a fast `no_agent` error, now reach the user after the acknowledgement. This holds even when `attachRun` is slow (tested with a 5 ms delay).
- `handleGraphEvent` now returns `{status:"handled"|"unknown_run"}` and no longer drops events silently. On `unknown_run` nothing is stored, and the relay should retry. The contract is documented in `docs/jarvis-channels.md`.
- **New tests:**
  - a fake graph emits `status` and a `no_agent` error inside `submit`;
  - an unlinked run returns `unknown_run`, and the event is handled once linked;
  - a live-push test against the real OVD-801 graph with "hello there" delivers the no-agent message.
  - Both N1 tests were checked to fail with the fix disabled.
- **Minor 1:** a retry whose own key already resolved the decision, or whose claim is still held when the graph answers `unknown_decision`, now counts as success instead of "refused".
- **Minor 2:** decision claims store `pendingAt`. A claim older than `decisionClaimTtlMs` (default 60 s, injectable clock) can be taken over.
- **Minor 5:** an inbound retry that has already been admitted (`findMessageByDedupeKey`) skips the rate limiter.
- **Schema (notes only, no SQL run):** two new nullable columns on `decisions`, `pending_at timestamptz` and `resolved_key text`. The claim-with-takeover becomes a single conditional UPDATE. The rate-limit retry check uses the existing unique `dedupe_key`.
- **Limitation:** holding early events only works within one process. Across processes, the relay relies on `unknown_run` and retries.
