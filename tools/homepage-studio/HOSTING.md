# Hosting Homepage Studio (runbook from an iPad)

Nothing in this repo creates a repo, a Vercel project, a secret or a deployment. Every step
below is performed by the owner (or by the orchestrator after the owner authorizes it, see
`hosted/CREATE-CHECKLIST.md`). The studio is built so the same code runs locally and hosted.

## How it fits together

```
iPad Safari  ->  Vercel project "homepage-studio" (static UI + api/[...route].mjs)
                    |  GitHub REST API (GITHUB_TOKEN, one private repo)
                    v
              PRIVATE data repo  <--  GitHub Actions workflow studio-generate.yml
              project.json, jobs/, versions/, baselines/      (runs Claude headlessly)
```

- Storage: the data repo. Every save is one commit `studio: <kind> <section> <versionId>`; no deletes, no force-push.
- Generation: the Claude CLI cannot run on Vercel, so the engine `github-actions` writes a job file,
  triggers the workflow, and the page polls the job (file plus workflow run status).
- The offline demo engine works hosted too, so the whole flow can be tried before any model credential exists.

## Environment variables

| Name | Where | Purpose |
|---|---|---|
| `STUDIO_HOSTED` | Vercel | `1` turns on hosted mode (password login, no loopback rule). |
| `STUDIO_PASSWORD` | Vercel | Shared login password. If unset, the API refuses everything (fails closed). |
| `STUDIO_SESSION_SECRET` | Vercel | 16+ chars (use 32+). Signs the 12 hour cookie. Unset or short: refuses everything. |
| `GITHUB_TOKEN` | Vercel | Fine-grained token for the data repo only. Without it (and `STUDIO_DATA_REPO`) the studio uses temporary storage and says so. |
| `STUDIO_DATA_REPO` | Vercel | `owner/name` of the data repo. |
| `STUDIO_DATA_BRANCH` | Vercel | Optional, default `main`. |
| `CLAUDE_CODE_OAUTH_TOKEN` | Data repo Actions secret | Primary model credential (Claude plan token). |
| `ANTHROPIC_API_KEY` | Data repo Actions secret | Alternative model credential (pay per use). |

## Steps

### a. Create the private data repo and copy the worker in
1. GitHub > New repository > name `optomachina/homepage-studio-data` (suggested), **Private**, tick "Add a README".
2. Seed and copy files (needs a computer with this repo checked out; the orchestrator can do it, see the checklist):
   `node tools/homepage-studio/scripts/seed.mjs --dir <clone of data repo> --with-baselines`, then copy
   `hosted/studio-generate.yml.template` to `.github/workflows/studio-generate.yml`, `hosted/worker.mjs` and
   `hosted/fetch-skill.mjs` to `studio/hosted/`, `lib/` to `studio/lib/`, `studio.config.json` to `studio/`.
   The exact commands are in `hosted/CREATE-CHECKLIST.md`.

### b. Create the GitHub token for the studio
GitHub > Settings > Developer settings > Fine-grained personal access tokens > Generate.
Repository access: **Only select repositories** > the data repo. Permissions: **Contents: Read and write**,
**Actions: Read and write**, Metadata: Read. Copy the token once; it goes into Vercel in step d.

### c. Add the model credential to the data repo (primary: Claude plan token)
1. On the owner's Mac, in Terminal: `claude setup-token`. Sign in if asked, then copy the long token it prints.
   **No agent can create or paste this token**; it is tied to the owner's Claude login.
2. On the iPad: the data repo > Settings > Secrets and variables > Actions > New repository secret.
   Name `CLAUDE_CODE_OAUTH_TOKEN`, paste the token, Add secret.
3. Alternative: a secret named `ANTHROPIC_API_KEY` with an Anthropic API key instead. Set one or both;
   if neither exists the worker records the job as BLOCKED with the exact message
   "No model credential configured in the data repo: add ANTHROPIC_API_KEY or CLAUDE_CODE_OAUTH_TOKEN" and produces nothing.

### d. Create a SEPARATE Vercel project
Vercel > Add New > Project > import this repository, but set: **Project name** `homepage-studio`,
**Root Directory** `tools/homepage-studio`, **Framework Preset** Other, no build command.
This must not be the main OverDrafter project. Add the environment variables from the table (Production).
Then Settings > Deployment Protection > **Vercel Authentication: on**. Deploy.

### e. First-run checks
1. Open the URL; Vercel asks you to sign in first, then the studio asks for the studio password.
2. No "Temporary storage" banner. If it shows, `STUDIO_DATA_REPO` or `GITHUB_TOKEN` is missing.
3. Page mode opens the v9 page full width (the baseline snapshot must be in the data repo, `seed.mjs --with-baselines`). Tap a headline, edit, Save; the data repo shows a commit `studio: manual ...`.
4. Pick the Demo engine and Generate; a version appears with the history icon, labelled "demo engine, not generated by a model".
5. Pick "GitHub Actions worker" and Generate; open the run in the Actions tab; the job turns Succeeded and a commit lands.
6. Log out, reload: the API answers 401 until you log in again.

## Page mode notes
- `ui/page-editor.js` is read by the API function at request time: `vercel.json` includes it in the function bundle (`includeFiles`).
  No new sensitive-path glob is introduced (nothing named like `lib/auth.mjs`); `lib/page-protocol.mjs` and `lib/page-parent.mjs` are plain
  shared modules, served unauthenticated like `lint.mjs` and `diff.mjs` (they hold no secrets).
- Baseline previews carry the editor and the same strict preview CSP (`sandbox allow-scripts`, no network). Hosted login, cookies and
  Vercel protection are unchanged; the sandboxed page never sends requests, the shell does.

## Cost notes
- Plan token: the run uses the owner's Claude plan allowance, no per-call bill, but heavy skills count against plan limits.
- API key: pay per use. The worker caps one run at about $3 (`--max-budget-usd`) and 30 minutes.
- GitHub Actions minutes are free for small private-repo use within the plan; Vercel Hobby covers this traffic. Check plan limits first.

## What the owner must authorize (nothing here does it on its own)
Creating the private repo, the fine-grained token, the model secret, the Vercel project and its env vars, and any paid
spend. Reviewing and approving the one-time pinned skill sources in `studio.config.json` (below).

## Third-party code the worker runs
- **No third-party GitHub Actions.** The workflow uses plain `git`, `curl` and `npm`, so there is no action SHA to approve.
- The Claude CLI is installed from npm, pinned by `CLAUDE_CODE_VERSION` (2.1.289, what the owner runs locally). Change it deliberately.
- Skills are fetched into the runner at the revision recorded in `studio.config.json`, and the run FAILS CLOSED on any mismatch:
  Anatomy `github.com/wheresryan22/anatomy` (commit recorded; read from a zip comment, confirm it), Anatomy-Asset
  `github.com/Teddarific/skills` @ `7e897b2c`, Machine Skill `github.com/AirsupHQ/machine-skill` @ `e0bd066a`,
  ISO-GLOW `https://isoglow.dev/iso-glow.zip` with the recorded sha256 of the reviewed copy. Re-review a skill before bumping its pin.

## Threat notes
- **Prompt injection.** The job prompt and the skill text reach a runner that holds a model credential. Mitigations: restricted
  tools (`Read,Write,Edit,Glob,Grep`, no Bash, no web), the model subprocess env holds only the model credential and never
  `GITHUB_TOKEN`, git credentials are passed per command and not stored in `.git/config`, output is a single HTML file that
  is contract-checked and shown only in a sandboxed iframe (no same-origin, strict CSP). Residual risk: egress filtering is
  not enforceable on hosted runners, so an injected run could still send the model credential or data to the network.
  Treat the model secret as exposed to whatever the prompt and skills contain: use a dedicated token, rotate on suspicion.
- **Token scope.** `GITHUB_TOKEN` (Vercel) can write only the data repo. The workflow uses the built-in token with `contents: write`.
- **Data repo is private**; it holds prompts, copy drafts and generated assets.
- **Two layers of login:** Vercel Authentication, then the studio password (rate limit is in-memory per instance, best effort,
  because serverless instances do not share memory) and a signed HttpOnly, Secure, SameSite=Strict 12 hour cookie.
- **Privacy:** no analytics, no third-party requests from the studio pages (CSP `default-src 'self'`).
- **Database:** none used. If Supabase or Vercel Blob is ever preferred, a DB change needs the owner's authorization and
  migrations are applied only by the owner.

## Not verified here
Nothing was run against real GitHub, Vercel or a model. The GitHub adapter, login, dispatch and worker are tested with a
fake fetch and fake git; the Vercel `fetch` export and `[...route]` catch-all follow Vercel's documented conventions but are
unproven until the first deploy.
