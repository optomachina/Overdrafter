# OVD-591 persistence interface (source contract; runtime qualification pending)

Every RPC is service-only, fixed-search-path, bounded JSON. No RPC performs network actions or grants admission. All mutations take advisory xact lock `(591,1)` before row/replay locks. This deliberately serializes small local transactions across scopes; no network work is permitted under this lock. Existing canonical record signature stays intact, with the same first lock and a scope high-water update.

`api_claim_capability_window(p_input jsonb)` takes exact keys:
`windowKey` (`canary:` followed by 64 lowercase hex), `resourceKey` (64 lowercase hex, service-owned provider/session identity hash; never a path), `configDigest` (64 lowercase hex), `requestKey` (UUID), `provider`, `route`, `surface`, `surfaceRevision` (existing ledger scope), `windowStart`, `windowEnd` (UTC ISO timestamps), `leaseSeconds` (integer 1..300).
It allocates a scoped safe-integer revision at reservation and returns `{status, windowKey, fence, generation:1, owner:requestKey, observationRevision, deadline}`. Only first `status=claimed` authorizes one probe. Replay returns `replay`; other claimants return `busy`; identity differences conflict. Resource exclusion spans windows; expiry does NOT free a resource or permit takeover. Completion frees it; ambiguity requires operator reconciliation outside this initial API. Gaps in revisions are intentional after abandoned reservations.

`api_get_capability_window(p_window_key text,p_request_key uuid)` recovers only the claimant's durable status/receipt; it never authorizes a probe or allocates a revision.

`api_complete_capability_window(p_input jsonb)` takes exact keys `windowKey`, `requestKey`, `fence`, `completionKey` (UUID), `resourceReleased:true` (trusted service attestation of confirmed profile/browser disposal), `candidate` (CapabilityRecordInput WITHOUT observationRevision; canonical scope must match reservation and actor/source must be scheduled_canary). Candidate idempotencyKey must equal windowKey. Fence is an immutable UUID; generation remains 1 because takeover is prohibited. Completion rejects expired fences and reservations older than the latest ledger revision. It appends through the existing canonical primitive and stores completion/receipt atomically. Exact replay returns the same receipt even after expiry; altered replay conflicts. Receipt: `{status:"completed",windowKey,observationRevision}`.

`api_read_capability_attention(p_scope_key text)` returns null or `{version,cursor,item,evidence}`.
`api_commit_capability_attention(p_input jsonb)` exact keys `expectedVersion` (0 for absence), `evaluationKey` (UUID), `cursor`, `item`, `intent`, `evidence` (projection evidence or null). Cursor/item/intent use existing pure projection shapes. Metadata determines canonical ledger scope. Under the shared lock, source observation revision and timestamps must equal the canonical resolver head (observedAt descending, then revision descending), preventing delayed stale evaluations from overwriting a newer ledger append before another evaluator advances the cursor. Cursor revision/time never regress, same revision retains same evidence hash, generation advances at most once. Separate CAS version increments even when generation stays unchanged. Exact evaluation replay returns same receipt; changed replay conflicts. Outbox intent is immutable, sanitized and unique; no delivery API. Evidence retains only classification/count-supporting bounded decision data, timestamps and revision (no raw provider response).
`api_list_due_capability_attention(p_limit integer)` returns at most 100 due state rows, service-only, for owner-controlled offline stale evaluation. Reads do not mutate or claim delivery.

Operational disable revokes execution of the new public RPCs after disabling consumers. Preserve all ledger, window, cursor, evaluation and outbox history; do not drop data or restore legacy record code while new reservations exist.

SQL, access-control, rollback and concurrency tests must run on a permitted disposable fixture before any durability claim. No production migration, live probe, delivery, registry fetch or enablement is included.

Status lookup returns `unknown` for missing/wrong-owner keys and `replay|expired|completed` for known ownership, never `claimed`. Busy claim returns only `{status:"busy"}`. Resource identity is service-owned and must stay consistent across configuration changes. The provider bridge MUST check receipt deadline against its clock immediately before entering the probe; a delayed response is not lease renewal.

The service owner must supply scopeKey, fingerprint, lastEvidenceHash and intent key from the existing trusted pure projector. SQL validates bounded shape, canonical metadata uniqueness, ledger identity/times, monotonicity, unchanged-revision evidence equality and transition algebra; it does not recompute JavaScript JSON serialization hashes or independently run admission/classification policy.
