# Registered result reader and internal runtime

Source only; no PostgreSQL, storage, Windows or native execution qualification is claimed.

`createNativeResultReader` loads the exact current task/attempt from private SQL, its frozen job/input snapshot, seven registered immutable object generations, and independently admitted process/filesystem context. Reads resolve registry Storage IDs internally and use the existing generation-aware private storage driver. The whole admission is reloaded and compared after all byte reads. Existing OVD561 SQL is the final locked authority check.

`createNativeResultRuntime` composes that reader with the seven-check verifier, exact-envelope durable persistence and existing finalization executor. `finalize` and explicit `replay` are internal owner operations. The default is disabled. Configuration supplies the already authorized owner SQL pool and receipt signing key directly. No environment lookup, credential setup or network call happens during composition. A private HTTP authentication/mount contract does not yet exist; this change deliberately adds no HTTP route.

## Additional migration purpose

`native-result-reader-forward.sql` adds one immutable owner-only attempt binding. Existing OVD575/576/577 evidence includes process identities and qualified stop provenance, but not independent input/candidate filesystem handle identities. Those cannot be learned from worker output reports.

The explicit owner admission writer takes independently captured filesystem identities and the SHA-256 of their retained qualification record. This is an owner attestation boundary, not automatic measurement or a claim that a hash establishes provenance. Only `postgres` may call the SQL writer; no public/service-role/worker grant is added. The operator must capture the two FILE_ID_INFO identities independently, bind the record to task, attempt, qualified evidence ID, host and both exact directory paths, retain its exact bytes, and calculate the digest. Never route worker filesystem JSON into this writer. A live independent capture integration is not supplied or qualified here.

The writer derives native and operation helper PID/start identities from existing independently validated and qualified journal launch roles, never caller process metadata. It rejects missing/foreign qualification, stale/current-attempt loss, revoked admissions, absent qualified successful stop, aliasing filesystem handles and changed replay. An exact replay returns the immutable prior process binding. SQL and TypeScript validate filesystem shape and reuse existing strict Windows path rules.
