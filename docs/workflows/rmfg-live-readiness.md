## Default-off switches

Nothing generated here enables RMFG. Each switch below stays off
until a reviewed change turns it on:

1. **Admission policy.** The `rmfg` admission policy stays `disabled`;
   the generator never approves it.
2. **Reviewed envelope.** `rmfg-quote-envelope` is listed in
   `REVIEWED_PROVIDER_DISPATCH_ENVELOPES` (OVD-687). That admits nothing until
   an active review row exists and the admission policy is approved.
3. **Live adapter.** The registry entry for `rmfg` is `liveAdapter: false`
   until the adapter lands and a reviewed edit flips it.
4. **Worker adapters.** `rmfg` is not in `WORKER_LIVE_ADAPTERS`, and the API
   key secret is declared by name only.

## Known gaps before admission

1. The API adapter is built on its own branch. It must call
   `rmfgDispatchAuthorizationDenial` before any request and add the case that
   proves no request leaves the worker on a denial.
2. Add `rmfg` to the worker `LIVE_AUTOMATION_VENDORS` only if the adapter
   joins the live automation path (a reviewed enum change).
3. Make one reviewed edit to the `rmfg` entry in
   `provider-integrations/provider-registry.v1.json`: `liveAdapter: true`. Then run
   `npm run provider:sync` and `npm run provider:check`. Never edit the generated
   `worker/src/generated/providerRegistry.ts` or
   `worker/scripts/generated/provider-secrets.sh`.
4. Confirm the `REVIEWED_PROVIDER_DISPATCH_ENVELOPES` entry for `rmfg` and
   apply the review-only admission SQL generated by
   `npm run fixture:onboard -- rmfg --stage=admit`, which stays a protected,
   reviewed action.
