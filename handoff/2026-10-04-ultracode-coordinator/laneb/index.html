Three visual directions for Lane B

DESIGN.md is the approved visual system and stays in force. This page asks you to pick between three directions for the visual questions it still leaves open. All three start from the same tokens and quoting rules. They differ on the signed-out entry, the JARVIS run surface and its diagrams, dark mode, and iOS shell polish.

Already decided

  • DESIGN.md is the approved system: bone paper, hairline rules, mono data, one oxidized-red accent, status as plain words.
  • Locked quoting patterns: fixed-dot scatter (X working days, Y quoted total, no lines), multi-quote stacking, US only / All sourcing with Unknown kept, quote-only 1.0 with hand-off to the provider and no ordering.
  • Approved iPhone target: INBOX | PARTS | QUOTES | MORE with ASK in the same row. The shell that ships today is Parts | Quotes | Search.

Open: what you are picking

  • Homepage and signed-out entry, including the GuestAppShell dark-gradient exception that survives on the password-recovery route.
  • JARVIS run surface and system diagrams.
  • Dark mode. The interim account toggle still uses the pre-redesign black palette.
  • iOS shell polish.

Not decided by this pick

  • Homepage headline and CTA copy. Mockups reuse shipped strings such as “CAD In / Parts Out” or a historical string. New copy is tagged PROPOSAL COPY — NOT APPROVED.
  • JARVIS’s customer-facing name. JARVIS is the working name.
  • All parts, prices, providers, run IDs, hashes and times are SAMPLE. The numbers differ between proposals, so compare the treatment, not the values.

Daylight Rigor, Finished

Finish DESIGN.md as written instead of inventing a new language. Every surface, including the signed-out entry and the JARVIS run screen, uses bone paper, hairline title-block cells, a condensed display face with mono data, plain-word status and one oxidized-red mark per screen. On the public page the sample part is the hero, not the OverDrafter brand.

Keeps from DESIGN.md

  • Tokens verbatim: bone #F2EFE8, surface, surface-2, hairline, warm black, one accent #C2410C used only for selection, decision or exception.
  • Radius 0/2/4, no shadows, no gradients, no glass, no illustration layer, no purple or blue.
  • Mono for every number, ID, hash, price, lead time and status word. Status is a word, never a color.
  • Quote Intelligence shell PARTS | QUOTES | SEARCH on web. Approved iPhone target INBOX | PARTS | QUOTES | MORE with ASK anchored in the same row.

  1. The signed-out home becomes a bone title-block page. A sample part filename (marked SAMPLE) is the 44–48px hero. It replaces the brand headline “CAD In / Parts Out” and the rounded 2×2 “How it works” cards with hairline cells.

  3. The JARVIS run screen uses the daylight system: a vertical hairline checkpoint list with the shipped phase labels, three separate cells for execution, verification and adoption, result cards that carry run and attempt identity, and a retained result labeled apart from a new build.

Conflicts with DESIGN.md (would need a Decisions-log row)

  1. Supersedes the 2026-05-14 row “GuestAppShell keeps a fixed dark pre-auth marketing shell”. Draft row: “2026-10-__ · Signed-out and recovery surfaces use the bone system; the GuestAppShell dark-gradient exception is retired · one daylight system pre- and post-auth; ‘Marketing surfaces follow the same system’.”
  2. No other conflicts. Recommended clarifying row (not a conflict): non-USD offers keep their original currency and are plotted lead-only, outside the USD axis.

PROPOSAL 2

Daylight Quoting, Night-Shift Engineering

Every surface where a buyer compares offers stays exactly DESIGN.md daylight: bone, hairlines, mono data, one red pencil mark. JARVIS run screens and system diagrams adopt the diagram treatment Blaine liked on Oct 3 as a deliberately designed dark “night shift”: charcoal canvas, thin outlined boxes, right-angle connectors, small mono labels, top-down flow with checkpoints. The same night tokens then become the deliberate dark mode DESIGN.md asks for, replacing the interim pre-redesign black palette.

Keeps from DESIGN.md

  • Bone #F2EFE8, warm ink, 1px hairlines, radius 0/2/4, no shadows, no gradients on every quoting surface, including the public homepage.
  • Oxidized red #C2410C as the only accent: one selection or exception per surface. Night shift uses the same hue, desaturated.
  • Mono for every number, ID and status. Status stays plain words, using the real phase names Claimed / Active / Awaiting results / Attempt failed / Recovery required.
  • Scatter-first comparison: fixed independent dots, X = working days, Y = quoted total, no lines. Chart, table and summary share one selection.
  • Xometry multi-offer stacking, US only / All sourcing with Unknown preserved, original currency with no FX conversion.
  • Web PARTS | QUOTES | SEARCH. iPhone INBOX | PARTS | QUOTES | MORE with ASK anchored in the same row.
  • 1.0 is quote-only. Selection hands off to the official provider, with no ordering or payment.

Changes

  • Adds night shift as the default for engineering/JARVIS surfaces and every system diagram: canvas #1A1B19, bone-tinted ink, the same 1px hairline rhythm, accent at about 18% less saturation (#DB5924).
  • Diagram grammar: outlined boxes, right-angle connectors, checkpoint words DONE / CURRENT / OBSERVED, and dashed boxes for paths not taken.
  • Role lanes in run diagrams: pale mint = execution, pale blue = verification, neutral grey = adoption. Tints color only the lane rule and lane label. The words always carry the meaning.
  • Night tokens replace the interim black palette behind the account dark-mode toggle. Quoting surfaces in dark mode get the night tokens but never the role tints.
  • The signed-out entry moves to daylight, so night shift is never a marketing backdrop.
  • Adds one ambient dot on the active run connector. It stops when reads are paused or stale, and under reduced motion.

Conflicts with DESIGN.md (would need a Decisions-log row)

  1. Role tints in diagrams vs “Single accent. No multi-color systems” and the anti-slop item “color used to encode status.” Tints encode lane role, never status, and are diagram-only.
  2. Pale-blue verification tint vs the “blue accent” anti-slop item. It is desaturated, never interactive and never an accent, but still needs a row.
  3. Lavender from the reference is dropped, because purple/violet is forbidden. This is logged as a decision so the reference cannot bring it back.
  4. Dark default for engineering surfaces vs “Daylight remains the default visual thesis” and the rejected defense-tech black.
  5. Night tokens replace the 2026-05-14 interim dark palette (“pre-redesign palette verbatim”).
  6. Retires the GuestAppShell exception (2026-05-14 row: fixed dark gradient pre-auth shell).
  7. Ambient looping dot vs Motion “Permitted”, which lists only state transitions, drawer, accordion and focus ring.
  8. Dark inset diagram on the public homepage vs “marketing surfaces follow the same system.” The diagram is framed and inset, never full-bleed.

Risks

  • Two modes can read as two products. Shared type, hairline rhythm and accent hue have to hold the brand together.
  • A charcoal canvas drifts toward the “war room” cliché DESIGN.md rejects. It needs restraint: no glow, no grid texture, no neon.
  • Role tints may creep into status coloring or quote tables. This needs a lint rule: lane tokens may only be used inside a diagram.
  • A moving dot can falsely imply live progress, so it must freeze when status is paused, stale or unavailable.
  • Pale tints on charcoal need contrast and color-blind checks. Lane words stay mandatory.
  • Engineering screens are development-only and gated today, so styling them now may run ahead of their contracts.

The Drawing Sheet

Make every primary surface a literal ASME-style drawing sheet: a zoned border so any region can be cited (“see C3”), a lower-right title block that carries identity, a revision block that records state history, and numbered general notes that hold assumptions and unknowns. DESIGN.md already borrows the title-block feeling; this proposal turns the sheet into the layout primitive itself. Palette, radius, elevation, motion and data rules stay exactly as they are. Only density and layout change.

Keeps from DESIGN.md

  • Bone #F2EFE8 / surface / hairline palette. Oxidized red #C2410C only for the current selection or one primary action. No purple, no blue.
  • Radius 0/2/4, no shadows, no gradients, no glass. Mono for every number, ID and status. Status is a plain mono word, never a colored badge.
  • Fixed independent-dot scatter (X working days, Y quoted total) with no connecting, trend or Pareto line. Chart and table share one selection.
  • Vendor multi-quote stacking, US only / All sourcing with Unknown preserved, and offers shown in their original currency.
  • Web shell PARTS | QUOTES | SEARCH. Approved iPhone shell INBOX | PARTS | QUOTES | MORE with a separate anchored ASK.
  • Quote-only 1.0: selecting an offer hands off to the official provider.

Changes

  • Zone frame around every primary surface. Numbers run 1–6 right to left and letters A–D bottom to top, as on ASME sheets, so zone A1 always sits at the title block. Phones use a 10px frame (1–4 / A–F).
  • Title block, lower right: part no., rev, qty, units, scale, date, sheet, run/attempt ID. On desktop part and quote detail it takes over the identity role of the 56px page header. On the homepage it is the upload invitation.
  • Revision block, upper right or inline: state history as rows. JARVIS phases become REV rows tied to an attempt. The homepage reuses it for the four existing workflow steps.
  • General notes with numbered flags (1) referenced from table cells, for unknowns, missing FX, expired offers and thread assumptions.
  • Homepage becomes one sheet. The dimensioned SAMPLE plate fills the drawing field.

Conflicts with DESIGN.md (would need a Decisions-log row)

  1. 56px page header (Quote Intelligence launch shell): part and quote detail move identity into the lower-right title block, and the header shrinks to a breadcrumb strip.
  2. Compact density / gutter rule: the zone frame uses 2×14px desktop and 2×10px phone width (≈5% of 375px). The title block adds roughly 120–170px of height to every primary surface.
  3. One primary scroll container: zone references only stay true on a fixed-size sheet. The sheet must either stay fixed while its field scrolls, or scroll with its content and let the zones drift. Both choices change the container contract.
  4. Locked status timeline (4 horizontal steps with dots): replaced by a tabular revision block for state history.
  5. “No illustrations” on the signed-out homepage: the dimensioned sample-plate drawing is offered as artifact, not decoration, but that call needs an explicit row.

Risks

  • REV letters normally mean released geometry revisions. Using them for run state can be misread as part revision C, D… Mitigation: the column reads STATE REV and the part revision stays in the title block. Numbered rows are the fallback.
  • On reflowing web layouts, “C3” points at different content on different viewports. The zones then become ornament, which DESIGN.md forbids.
  • Pastiche: heavy drafting chrome can read as a costume and slow scanning in dense tables.
  • On narrow homepages the lower-right title block (and its CTA) falls below the fold, so it has to be reordered above the notes, which breaks the conceit.
  • Zone labels at 7–9px carry no information for screen readers (they are hidden) and are hard to read for low-vision users.
  • Build cost: new Sheet / TitleBlock / RevisionBlock / Notes primitives across web and the WKWebView iOS shell.

Every quote, eligibility line, run ID, hash and timestamp below is SAMPLE data. Copy tagged PROPOSAL COPY — NOT APPROVED is new. No frame shows ordering, payment or “place order”.

How to choose

One question for Blaine

Which direction should Lane B implement: Proposal 1, 2, or 3 — or a named mix?

Pick 1 if

you want one daylight system before and after sign-in, the fewest Decisions-log rows and the smallest build. JARVIS stays on bone.

Pick 2 if

you want the Oct 3 dark diagram look for JARVIS and a designed dark mode, and you accept eight Decisions-log rows and the guardrails they need.

Pick 3 if

you want the drawing sheet as OverDrafter’s signature layout, and you accept the largest build and the reflow and accessibility risks.

A mix works if you name which proposal owns each open question: signed-out entry, JARVIS and diagrams, dark mode, iOS shell. Proposal 1 already suggests one, which is its daylight system everywhere with Proposal 2’s night-shift style kept for documentation diagrams only.
