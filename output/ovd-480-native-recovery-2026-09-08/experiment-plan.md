# OVD-480 bounded native ownership and recovery experiment

Status: preparation; no native operation authorized by this artifact alone.

User direction: proceed with worker isolation and native recovery after the six merged CAD foundations. Selected environment remains Workstation / SolidWorks 2022 SP5; experimental Windows Home acceptance persists.

Acceptance criteria for this increment:
- Freshly observe application process and document state and preserve exact synthetic baseline identities.
- Establish a separately retained native Process handle and cross-check executable hash, session, provider-consistent creation identity and API GetProcessID before experimental native mutation or forced termination.
- Use a new directory and copy of the previously verified 5 mm cylinder for each attempt. Verify original hashes before and after.
- Demonstrate one clean open/edit/rebuild/save/read-only-reopen lifecycle in the owned instance before admitting interruption.
- At a flushed post-edit/pre-save checkpoint, record the controlled interruption's actual target, phase and exit. Never label helper termination as native termination.
- Recover only after prior native exit is confirmed, using a fresh attempt and unchanged baseline, then repeat mandatory native and geometry checks.
- Preserve all unsuccessful attempts and report shared-profile, filesystem/network, crash/hang/save-interruption and licensing limitations explicitly.

Boundaries:
- Synthetic files only; no customer CAD, PDM, authoritative files, license/settings/security changes, installations or broad process termination.
- No kill-by-name, discovered-PID termination, COM-created-instance ownership assumptions, or reuse of an unknown application state.
- A private directory and owned process do not qualify an OS sandbox or deployment entitlement.
- Full worker queue, fencing enforcement, lease recovery and customer pilot remain separately scoped.

Execution budget: first qualification pass 30 minutes, one implementation/design review, one attempt per admitted case and at most one repair run for a diagnosed failure. If current machine state prevents an owned lifecycle, preserve the failed prerequisite and continue the independently useful tooling work.
